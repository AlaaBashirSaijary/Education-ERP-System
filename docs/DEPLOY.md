# النشر

يعمل التطبيق في حاوية واحدة (Apache + PHP 8.3) تشغّل الويب وعامل الطابور (رسائل الأهل) والمجدول (إغلاق الحضور وتذكير الأقساط).
يلزمك أي استضافة تشغّل `Dockerfile` من مستودع GitHub، مع قاعدة بيانات **PostgreSQL** (أو MySQL) من الاستضافة نفسها.
لا تستخدم SQLite في الإنتاج: قرص الحاوية يُمسح عند كل نشر.

## الخطوات
1. أنشئ قاعدة PostgreSQL في الاستضافة وانسخ رابط الاتصال.
2. أنشئ خدمة جديدة من هذا المستودع (الفرع الذي تريده). ستكتشف الاستضافة `Dockerfile` تلقائياً.
3. أضف المتغيرات:

| المتغير | القيمة |
|---|---|
| `APP_KEY` | ناتج `php artisan key:generate --show` (أو `base64:` + `openssl rand -base64 32`) |
| `APP_URL` | عنوان الموقع، مثل `https://school.example.com` |
| `DB_CONNECTION` | `pgsql` (أو `mysql`) |
| `DB_URL` | رابط قاعدة البيانات، مثل `postgresql://user:pass@host:5432/db` |
| `SESSION_DRIVER`, `QUEUE_CONNECTION`, `CACHE_STORE` | `database` |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | حساب المدير الأول (8 أحرف على الأقل). يُنشأ عند الإقلاع إن لم يوجد مدير. |
| `MESSAGING_CHANNEL` | `log` للتجربة، ثم `whatsapp` أو `sms` مع مفاتيح المزوّد |

   `APP_ENV=production` و`APP_DEBUG=false` و`TRUSTED_PROXIES=*` مضبوطة في الصورة.
4. انشر. عند الإقلاع تُنفَّذ الـ migrations تلقائياً. افتح الرابط وادخل بحساب المدير.
5. بعد الدخول، أضف الصفوف والمواد من صفحة «الإعداد»، ثم المعلمين من «المستخدمون».

لا تشغّل `DemoSeeder` في الإنتاج (يرفض ذلك). للبيانات التجريبية استخدم بيئة منفصلة.

## ملاحظات
- لم أبنِ هذه الصورة بـ Docker (لا يوجد Docker daemon في بيئة التطوير). جرّبت خطوات الإقلاع نفسها (migrate، إنشاء المدير، التخزين المؤقت، الويب، الطابور) على PostgreSQL 16 بوضع الإنتاج.
- `TRUSTED_PROXIES=*` مناسب خلف موازن الاستضافة. إن كشفت الحاوية مباشرة للإنترنت فاضبطه على عناوين الموازن فقط.
- النسخ الاحتياطي لقاعدة البيانات مسؤوليتك: فعّله من الاستضافة.
- بديل بلا Docker: Laravel Cloud أو Forge (يعتمدان على المستودع ويشغّلان `migrate` و`queue:work` و`schedule:run`).
